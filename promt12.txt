MarketPilot — Phase 1: Stabilization & Production Readiness

Ты работаешь над существующим проектом MarketPilot — SaaS-платформой для управления Telegram-каналами, группами и сообществами.

Твоя задача — провести технический аудит текущей реализации, устранить обнаруженные архитектурные недостатки и довести существующие модули до стабильного состояния.

ВАЖНО: НЕ ПЕРЕПИСЫВАЙ ПРОЕКТ С НУЛЯ. НЕ УДАЛЯЙ СУЩЕСТВУЮЩИЕ ФУНКЦИИ. НЕ ЛОМАЙ СУЩЕСТВУЮЩИЕ API И ИНТЕРФЕЙС.

1. Текущий технологический стек

* Python backend.
* SQLite с WAL.
* Vanilla JavaScript.
* HTML/CSS.
* Telegram Bot API.
* Telegram Mini App.
* YooKassa Marketplace.
* Background Scheduler.
* Workspaces и RBAC.
* Интеграционные тесты.

Сохраняй текущий стек. Не мигрируй на FastAPI, React, PostgreSQL, Redis или Celery без отдельного обоснования и согласования.

2. Account Billing — исправление подписок

Реализуй полноценный жизненный цикл подписок аккаунтов.

Необходимо:

* Автоматически проверять ends_at.
* Автоматически переводить пользователя на FREE после окончания оплаченного периода.
* Реализовать корректную отмену подписки.
* Сохранять историю платежей и продлений.
* Предотвращать повторное списание.
* Отправлять уведомления об окончании подписки.
* Проверять подтверждение платежа на сервере.
* Исключить возможность самостоятельной активации платного тарифа без подтверждённой оплаты в production.

Не путай подписки аккаунта MarketPilot с подписками пользователей платных Telegram-сообществ. Это два отдельных платёжных контура.

3. Workspace и RBAC

Проведи полный аудит изоляции рабочих пространств.

Реализуй:

* Корректную передачу workspace_id в фоновые задачи.
* Проверку membership перед выполнением критических действий.
* Проверку актуальных прав пользователя.
* Строгую изоляцию данных между workspace.
* Корректную работу owner, admin, moderator и viewer.
* Защиту от доступа к чужим ресурсам через подмену ID.

Проверь все API-эндпойнты, связанные с публикациями, модерацией, рекламой, настройками, платежами и ресурсами.

4. Audit Log UI

Создай полноценный раздел «Журнал действий».

Возможности:

* Просмотр истории действий.
* Имя и ID пользователя.
* Тип действия.
* Дата и время.
* Рабочее пространство.
* Фильтрация по пользователям.
* Фильтрация по категориям событий.
* Фильтрация по периоду.
* Пагинация.

Учитывай текущую таблицу audit_log. Не создавай дублирующую систему журналирования.

Не сохраняй секреты, токены, пароли и полные тела запросов.

5. Scheduler Reliability

Проведи аудит планировщика публикаций.

Реализуй и проверь:

* Защиту от дублирования публикаций.
* Корректную обработку статусов publishing, published, failed, cancelled, unknown.
* Обработку HTTP 429 и retry_after.
* Обработку HTTP 400 и 403.
* Контроль зависших задач.
* Корректную работу после перезапуска сервера.
* Контроль часовых поясов.
* Ограничение запросов Telegram API.
* Корректную отмену запланированных задач при отключении ресурса.

Особое внимание удели неизвестному результату отправки. Не допускай автоматического повторения публикации, если Telegram мог уже принять сообщение.

6. Production Security

Проведи аудит безопасности.

Проверь:

* Telegram initData.
* Сессионную авторизацию.
* Проверку Origin.
* CSRF-защиту.
* Rate limiting.
* RBAC.
* Изоляцию пользователей.
* Загрузку файлов.
* Безопасность webhook платежей.
* Хранение секретов.
* Удаление аккаунтов.
* Защиту от повторных запросов и атак на API.

Добавь безопасное резервное копирование SQLite и проверку восстановления базы.

Не допускай попадания .env, токенов и пользовательской базы в публичные архивы или Git.

7. Рефакторинг backend

Текущий api.py слишком большой.

Постепенно раздели бизнес-логику на логические модули, например:

* auth.py
* workspaces.py
* resources.py
* publications.py
* billing.py
* moderation.py
* analytics.py
* notifications.py
* advertising.py

Не делай массовый рефакторинг без необходимости. Сохраняй совместимость API и существующие бизнес-правила.

8. Тестирование

Для каждой изменённой функции добавляй тесты.

Обязательно проверь:

1. Истечение подписки.
2. Отмену подписки.
3. Повторные платежные события.
4. Изоляцию двух рабочих пространств.
5. Проверку ролей.
6. Параллельную обработку публикаций.
7. Перезапуск Scheduler.
8. Ошибки Telegram API.
9. Доступ к чужим ресурсам.
10. Удаление аккаунта и связанных данных.

Запусти полный существующий тестовый набор.

Нельзя удалять тесты или ослаблять проверки ради получения успешного результата.

9. Критерии завершения

Работа считается завершённой, если:

* Все существующие функции продолжают работать.
* Новые тесты проходят.
* Нет критических проблем с изоляцией данных.
* Нет возможности обходить платёжную систему.
* Нет дублирования публикаций.
* Workspace-контекст учитывается фоновыми задачами.
* Журнал действий доступен через интерфейс.
* Проект запускается по существующей инструкции.
* Документация соответствует фактической реализации.

10. Формат работы

Работай последовательно:

1. Изучи весь проект.
2. Составь список обнаруженных проблем.
3. Определи зависимости между ними.
4. Сначала устрани критические проблемы.
5. Реализуй изменения небольшими логическими блоками.
6. После каждого блока запускай соответствующие тесты.
7. Исправляй регрессии.
8. Обновляй документацию.

Не ограничивайся рекомендациями и описанием того, что нужно сделать. Реально изменяй файлы проекта.

Не создавай фиктивные функции, заглушки и интерфейсы без работающего backend.

Не отмечай функцию как реализованную, если она только появилась в интерфейсе.

В конце предоставь отчёт:

* Что исправлено.
* Какие файлы изменены.
* Какие функции добавлены.
* Какие тесты пройдены.
* Какие проблемы остались.
* Что рекомендуется реализовать следующим этапом.

Главная цель: превратить существующий MarketPilot v0.2 в надёжную основу коммерческого SaaS-продукта, сохранив всю существующую функциональность.
